# JenAI v2.3.0

**v2.3.0 makes long-running robot inspection workflow-first: the LLM selects one
high-level capability, deterministic code executes the normal mission, and ROS 2/Nav2
remain responsible for navigation and motion.**

## Workflow-first semantic patrol

- Natural-language requests for complete site inspection route to one bounded
  `area_patrol_workflow` tool instead of an LLM-selected sequence of primitive goals.
- The workflow loads required semantic areas from the active Site Profile, performs
  bounded navigation retries, captures evidence, tracks coverage, returns home, and
  emits a typed report.
- Ordered waypoint patrol and random exploration remain separate capabilities; semantic
  patrol does not claim unknown-map geometric or frontier coverage.
- A dependency test keeps the workflow domain independent from ROS 2, Nav2, Isaac Sim,
  providers, CLI, TUI, and WebUI. Production and in-memory adapters share one small
  runtime seam.

## Honest evidence and outcomes

- Observation coverage now requires evidence at every required inspection point and is
  independent from semantic clearance. Covered areas that need review are reported in
  `review_required_areas`; missing evidence never counts as coverage.
- Vision prompts and deterministic normalization reject normal-state prose such as
  “safe,” “orderly,” “no people,” or “simulated appearance” as anomalies while
  preserving concrete deviations such as spills.
- Long missions stream target, remaining distance, elapsed time, recovery count,
  inspection, evidence, and return-home progress.
- Untrusted model output is escaped before Rich rendering, preventing bracketed text
  from crashing the TUI after approval.

## Site, ROS, and documentation hardening

- Site Profile onboarding, validation, repair, migration, map identity, location
  binding, and product documentation now share one contract.
- ROS health discovery can bypass stale daemon state and uses the configured Jazzy
  workspace in the documented Isaac/Nav2 startup path.
- The NVIDIA-inspired documentation website builds and tests as a standalone packaged
  documentation application.
- The local-only thesis was advanced to v21 with the workflow architecture, supervised
  acceptance evidence, limitations, and corrected manual page references. Thesis files
  remain excluded from GitHub.

## Candidate validation

- Ruff formatting and lint pass.
- Strict mypy passes for all 125 production source files.
- All 1,048 pytest cases pass.
- Overall branch coverage is 78% against a 76% gate; the safety chain is 94% against a
  90% gate. The workflow domain is 98% and its Agent adapter is 93%.
- Documentation website rendered-page tests and production build pass.
- Wheel and source distribution build successfully.
- One supervised Isaac Sim/Nav2 run selected one workflow, visited four required
  inspection areas, saved four evidence images, and returned to Dock with 0.037 m
  position error and 0.149 rad yaw error. It exposed a historical coverage/reporting
  defect that is preserved in the artifact and fixed by regression tests.

The live run is descriptive simulation engineering evidence, not a physical-vehicle,
charging, VLM-accuracy, unknown-map coverage, or long-term reliability claim. A complete
post-fix live rerun, physical docking feedback, quadruped adapter validation, and
self-hosted ROS sidecar coverage remain follow-up work.

GitHub CI, merged revision, release assets, dependency audit, SBOM, checksums, and
provenance claims become authoritative only after the corresponding remote workflows
and published release pass.
